# サブシステム設計書一括生成 — 設計仕様

> **Created:** 2026-07-06
> **Status:** Approved
> **Scope:** `subsystems/` 下の全 82 プログラムの設計書を「1 プログラム = 1 設計書」で作成するワークフローとテンプレの定義

---

## 1. 背景と目的

本リポジトリは GitHub Copilot Quest Lv.3 の題材として、**ドキュメントとコメントを意図的に除去した**レガシー COBOL 資産である。動く実行コード・ビルド/テスト資材のみが残り、業務仕様はコードから逆推論するしかない。

本仕様は、**22 サブシステムに散在する 82 プログラム**を対象に、AI にコードを解析させて設計書を復元・生成するワークフローと、出力テンプレを定めるものである。目的は：

1. 各プログラムの **業務要件・ロジック・データフロー** を復元し、保守可能にする
2. プログラム間の **依存関係・データの流れ** を可視化する
3. 後の **Azure モダナイズ** の一次資料とする

---

## 2. スコープ

### 2.1 対象

- **配置**: `subsystems/NN-name/src/` 下の全プログラム
- **言語**: COBOL（`.cob`）、埋め込み SQL（`.sqb`）、生成ソース（`.cob.gen`）
- **総数**: 82 プログラム / 22 サブシステム

### 2.2 対象外

- `shared/` 配下のユーティリティ（設計書生成の**入力**にはなるが設計書の主語にはしない）
- `console/`、`tests/`、`db/migration/` の成果物自体（参照・解析対象）
- 既存のトップレベル markdown（README.md 等）の書き換え

### 2.3 成果物

- `subsystems/NN-name/design/_template.md` — テンプレ（全サブシステム共通、生成時にコピー）
- `subsystems/NN-name/design/<program-name>.md` — 各プログラムの設計書（日本語、lower-case ファイル名）

---

## 3. 設計書テンプレ（10 セクション）

各設計書は以下の 10 セクションで構成する。**Full 分析級**。

| # | セクション | 必須 | 内容 |
|---|-----------|:----:|------|
| 1 | **プログラム概要** | ✅ | PROGRAM-ID、所属サブシステム、目的（1-2 文）、種別（オンライン/バッチ/LOAD/配信） |
| 2 | **業務要件（再構築）** | ✅ | コードから推定されるビジネスドメイン・業務目的。コメントなしを前提に **コードが何をしているかから逆推論** |
| 3 | **入出力インターフェース** | ✅ | `LINKAGE`/`USING`、`COPY "api.cpy"`（公開）と private cpy（内部）を区別、ファイル OPEN モード |
| 4 | **業務ロジック / ルール** | ✅ | EVALUATE/IF/PERFORM から復元した判定ルール・計算式・状態遷移。**根拠コードへの行参照**をつける |
| 5 | **データアクセス** | ✅ | READ/WRITE/UPDATE/DELETE するファイル・ISAM インデックス・PostgreSQL テーブル。DDL（`db/migration/`）との突き合わせ |
| 6 | **プログラム間呼出** | ✅ | `CALL "X"` の外部呼び出し、サブシステムを跨る依存を明示 |
| 7 | **エラー処理・ステータスコード** | ✅ | 返却コード体系、ファイル STATUS、SQLCODE 取り扱い |
| 8 | **データフロー・シーケンス** | ✅ | **Mermaid 図**（flowchart / sequenceDiagram）で入力→処理→出力、ファイル/メッセージブローカ経由の流れ |
| 9 | **テストカッバレッジ** | ✅ | `tests/unit/` のテストプログラムが本プログラムのどの分岐を保証。**不在の明示**も価値 |
| 10 | **モダナイズ候補** | ✅ | Azure 移行時の候補（Functions / Container Apps / Service Bus 等）、リファクタ観点での懸念点 |

### 3.1 セクションの凡例

- **コード参照**: 該当する `src/` を行番号付きで引用（例: `src/cal-next-bd.cob:34-57`）
- **コピーブック参照**: `copy/api/cal-api.cpy` / `copy/private/ws-cal-cache.cpy` のように区別
- **図**: GitHub Markdown の ` ```mermaid ` フェンスを使用
- **相互参照**: 相対パスで他プログラム設計書へリンク（例: 同サブシステム内 `[CAL-LOOKUP](../01-calendar/design/cal-lookup.md)`、サブシステム跨ぎ `[branch-lookup](../../02-branch/design/br-lookup.md)`）

## 4. 配置規約

```
subsystems/NN-name/
├── design/
│   ├── _template.md              ← テンプレ（セクション定義・凡例）
│   ├── cal-next-bd.md            ← プログラム設計書
│   ├── cal-prev-bd.md
│   └── ...
├── src/
├── copy/
├── data/
├── bin/
├── tests/
└── Makefile
```

- **ファイル名**: プログラム名を **lower-case + `.md`**（例: `CAL-NEXT-BD` → `cal-next-bd.md`）
- **テンプレ**: `_template.md` に置き、全サブシステム共通
- **言語**: 日本語
- **相互参照**: 相対パスで記述

## 5. 生成ワークフロー

### Phase 0 — 仕様確定（本ドキュメント）

本仕様書のレビュー・承認。

### Phase 1 — サンプル作成

- **サンプル対象**: `01-calendar` の 4 プログラム（cal-next-bd, cal-prev-bd, cal-lookup, cal-load）
  - 選定理由: セッション開始時に精査済み、典型的なバッチパターン（CALL 内部モジュール化、EVALUATE ステータス返却）、10 セクション全てが埋められる好例
- テンプレ `_template.md` + 4 本の設計書を `subsystems/01-calendar/design/` に直接作成

### Phase 2 — ユーザーレビュー

- テンプレ＋手本をレビュー依頼
- 修正案を反映し、テンプレを**確定**する

### Phase 3 — 並列生成

- **粒度**: サブシステム = 1 エージェント（計 22 エージェントを parallel 起動）
- **入力**: 確定テンプレ + 01-calendar 手本 + 担当プログラム群のコード/コピーブック/テスト/Makefile
- **出力**: 各 `subsystems/NN-name/design/*.md`
- **エージェント役割**: 「コード解析 → 設計書作成」を自律実行。外部依存は相対パスでリンク

### Phase 4 — 一貫性レビュー

全 82 枚完成後に **一括レビュー エージェント**を起動。観点：

- 用語統一（「営業日」「祝日」「営業日」等の揺れ）
- 図スタイル統一（Mermaid の書式）
- 相互リンク解決（リンク切れ検出）
- ステータスコード表記揺れ
- 自動修正可能なものはインライン修正

### Phase 5 — コミット

- `docs/superpowers/specs/` コミットで仕様書をコミット
- `subsystems/*/design/` コミットで設計書をコミット

## 6. リスクと対策

| リスク | 対策 |
|--------|------|
| 並列 22 エージェントが上限に触れない | サブシステム = 1 agent で 22 体。上限(1000)クリア |
| `.gen` ファイルの扱い | テンプレで「gen は生成ソース。.sqb と対」と明記、`.sqb` ベースで解析 |
| コピーブックの循環参照 | サブシステム内は private、跨る共有は `shared/copy/` を指す |
| レビュー待ちボトルネック | Phase 2 は **テンプレ＋4 本レビュー**に限定し早期固定 |
| 品質ばらつき | テンプレ＋手本で「完成形」を先に見せ、並列生成時に参照させる |

## 8. 用語集（生成時に共通で使用）

| 用語 | 意味 |
|------|------|
| 営業日 (Business Day) | カレンダー上で営業とみなされる日（祝日・週末を除く） |
| ステータスコード | プログラムが GOBACK 時に返す 2 桁の数値（00=正常, 04=レコードなし, 08=入力エラー 等） |
| コピーブック (Copybook) | COBOL の `COPY` 文で取り込むデータ定義（`.cpy`） |
| 公開インターフェース | `copy/api/*.cpy` に定義された外部公開 LINKAGE |
| 内部インターフェース | `copy/private/*.cpy` に定義されたサブシステム内専用 LINKAGE |
| ISAM インデックス | `.idx` ファイルによるインデックス付きファイルアクセス |
| バッチ | 一括処理（日次/月次） |
| モダナイズ候補 | Azure 移行時のサービス候補 |
